# Strategy Document

> 🔒 **Locked.** Operator only. The CEO allocates capacity against this file and nothing else.
> 🔒 **잠금.** 운영자만 수정합니다. CEO는 오직 이 파일을 기준으로 용량을 배분합니다.

---

## English

Fill in this template monthly (see `governance/audit-ritual.md`). Keep it short: the CEO must be able to justify every allocation by pointing at a line here.

```markdown
# Strategy — <period>

## Mission
One sentence.

## Objectives this period (max 3)
| # | Objective | Measurable target | Why it matters |

## Portfolio
| Project | Class | Capacity share | Notes |
|---|---|---|---|
| <project-a> | core        | 60% | the main bet |
| <project-b> | experiment  | 15% | fixed weekly budget; kill criteria below |
| <project-c> | maintenance | 10% | bugs and docs only |
| brand        | brand       | 15% | drafts auto; publishing per policy |

Classes: core (most capacity), experiment (capped, has kill criteria),
maintenance (bugs, security, docs only), brand (content and community).

## Kill criteria for experiments
| Project | Stop if | Review date |

## Non-goals
Things the company must not spend capacity on this period, even if they look promising.

## Constraints
Budget ceilings, deadlines, things the Operator will not do.
```

## 한국어

매월 이 템플릿을 채웁니다(`governance/audit-ritual.md` 참조). 짧게 유지하세요. CEO가 모든 배분을 여기의 한 줄을 가리키며 정당화할 수 있어야 합니다.

- **미션**: 한 문장
- **이번 기간 목표**: 최대 3개, 측정 가능한 목표치와 이유
- **포트폴리오**: 프로젝트별 등급과 용량 비율. 등급은 코어(대부분의 용량), 실험(상한이 있고 중단 기준이 있음), 유지(버그·보안·문서만), 브랜드(콘텐츠·커뮤니티)
- **실험 중단 기준**: 언제 멈출지, 언제 재검토할지
- **하지 않을 것**: 유망해 보여도 이번 기간에 용량을 쓰지 말아야 할 것
- **제약**: 예산 상한, 마감, 운영자가 하지 않을 일
